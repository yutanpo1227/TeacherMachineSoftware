# 実機の症状から制御をたどる

1. ルートの README と対象ファイルを読み、実機に書き込まれた版、攻守モード、攻撃色を確認する。作業ツリーの設定と実機の版は分けて扱う。
2. 症状が起きる場面で、センサー値と制御の状態を対にして見る。受信ログの `state`、`ball`、`ir`、`cameraBall`、`yaw`、`error`、`line`、`lineUsed`、`ownRear`、`bottomGap` が手がかり。守備ログのラインは別インスタンスの表示値なので、攻撃の制御入力と一致するとは限らない。
3. 調整点を一つに絞り、実機動作とコードの対応を説明する。試験方法は README の「検証」を使う。実機にアクセスできる場合は、状態と出力を確認してから床上の挙動と照合する。

- **ゴールや左右が合わない**：物理上のミラー名から画像の左右を推定せず、実際に対象を置いてROIと角度を確認する。機体座標は右0°、前90°、左180°、後ろ270°。BNO055の角度は別基準で、電源投入方向で自動ゼロ化されない。`bottomGap` は画素値なので、姿勢や見切れを含めた実機校正が必要。
- **止まる・遅い**：白線、ボール未検出、姿勢差、ゴール近接、カメラ通信断の各分岐を先に確認する。PWM指令と実際の速度を分ける。負荷時の電池パックとモータードライバー入力を同じ走行条件で測ると、電池側と配線側の電圧降下を切り分けられる。
- **攻守切替**：攻撃への切替は前方カメラの連続検出で計時し、走行は単独OFFENSEと共通。白線離脱は切替時の限定処理。ゴール未検出での復帰はカメラ通信断と区別し、ジャイロ整列から後退・探索までを順に確認する。
- **通信**：ArduinoとMacのUSBログ、カメラとArduinoのUART、MaixPy IDEのカメラUSBは別経路。USBシリアルモニターの競合とArduinoの接続時リセットに注意する。カメラの設定を変える際は `V-mirror.py.autosave` に未反映の色閾値がないか確認する。 コマンド、ログの保存・読み方、書き込み手順は [Arduino CLIとシリアルデバッグ](references/arduino-serial.md) を参照する。
- **競技仕様**：ボールの検出調整、練習コートの寸法、ゴールや白線の扱いを確認するときは [2026年のボール・フィールド仕様](references/competition-specs-2026.md) を参照する。

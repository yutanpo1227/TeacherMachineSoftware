# V字ミラーカメラの仕組み

このページでは、先生のマシンがカメラ1台で前後のボールとゴールを見つけ、その方向をArduinoへ伝える方法を説明します。使用するカメラは[UnitV AI Camera（OV7740、M12レンズ版）](https://www.switch-science.com/products/9182)です。対象はMaixPy v1で動作する [`camera/V-mirror.py`](../camera/V-mirror.py) と、受信側の [`Camera`](../lib/Camera/) ライブラリです。

## 何を見ているか

カメラは上向きに取り付け、その上にV字の2枚の鏡を置いています。各面に映る景色を1枚の画像に収めることで、前後を同時に観測します。側方を含め、鏡や柱で見えない場所もあります。

現在の設定は320 × 240画素のQVGA画像を次の2領域に分けます。

| 対象 | 画像の位置 | 設定値 `(x, y, 幅, 高さ)` |
| --- | --- | --- |
| 前方ミラー | 画像の右側 | `ROI_FRONT = (150, 0, 160, 240)` |
| 後方ミラー | 画像の左側 | `ROI_BACK = (0, 0, 150, 240)` |

この「右・左」は**画像上の位置**です。物理的に左にある鏡が画像の左に映るとは限らないため、鏡の名前だけで前後を決めないでください。実際に機体の前側、後ろ側へ順に対象物を置き、どちらの領域に映るか確認してから設定します。対象物を探す範囲をROI（Region of Interest、注目領域）と呼びます。

## 画像から色を検出する

1. カメラでRGB画像を撮影し、前方と後方のROIをそれぞれ調べます。
2. オレンジ、黄色、青のそれぞれについて、LAB色空間の閾値に入る画素を探します。LABは明るさと色の成分で色を表す方法です。
3. 隣接する画素をひとまとまりの **Blob（色のかたまり）** として検出し、小さいノイズを除いてから、ROI内で画素数が最大のBlobを採用します。
4. 採用したBlobの位置を機体に対する角度に変換し、Arduinoへ送信します。

設定する値は `ORANGE_THRESHOLDS`、`YELLOW_THRESHOLDS`、`BLUE_THRESHOLDS` です。各値は `(L最小, L最大, A最小, A最大, B最小, B最大)` の順です。照明や鏡の反射によって映る色は変わるため、会場で使用するボール・ゴールを**鏡越しに**撮影し、対象が枠で囲まれるか調整します。床や周囲の同じ色まで拾っていないかも見ます。画像上の矩形は検出結果であり、対象の正確な輪郭ではありません。

`BLOB_PIXELS_THRESHOLD` と `BLOB_AREA_THRESHOLD` は検出するかたまりの最小サイズ、`BLOB_MERGE_MARGIN` は近くの領域をまとめる際の余裕です。値が大きすぎると、遠くに見える小さな対象を検出しにくくなります。

### ボールとゴールの扱い

ボールは前後の候補から1つだけをArduinoへ送ります。両方に候補があるとき、反対側の画素数が現在の側の `VIEW_SWITCH_PIXELS_RATIO` 倍を超えるまで現在の側を維持し、前後の切り替わりによる揺れを抑えます。候補がなくなると採用側も解除されます。

ゴールは黄色・青色それぞれについて、前方と後方の情報を独立して送ります。守備中は自ゴールの後方ミラー側の検出を使います。攻撃用に色だけを指定して問い合わせる場合、Arduinoは前方に同じ色の検出があれば前方を優先します。周囲の黄色や青色の物体も同じ色として検出されるため、実物と枠を見比べてください。

## 画像座標から方向へ

このマシンでは、機体の左右方向が画像の **y軸** に沿って映ります。Blobのy位置を中心線からのずれとして使い、前方は正面90°、後方は真後ろ270°を基準に機体の方向へ換算します。機体座標は右0°、前90°、左180°、後ろ270°です。

`MIRROR_VIEW_FOV_DEG` は画像の縦方向に割り当てる視野角で、現在は80°です。`FRONT_CENTER_POS` / `BACK_CENTER_POS` が `None` の場合、各ROIのy方向の中央を正面として扱います。`FRONT_ANGLE_SIGN` と `BACK_ANGLE_SIGN` は、対象を左右へ動かしたときに角度が増える向きを決めます。角度は中心からの画素位置を線形に換算した近似値です。

ボールと前方ゴールの方向にはBlobの重心を使います。後方ゴールは、見えているBlobを囲む矩形のy方向の中点を使います。これは見えている部分の中心なので、ゴールが画面から切れている場合はゴール全体の中心とは限りません。

ゴールの `span` は画像上のy方向の両端を角度に換算した**角幅（度）**です。y方向に見切れた場合は `-1` になります。一方、後方ゴールの `bottomGap` は後方ROIの中央側の境界から検出矩形のx方向の端までの**画素数**です。y方向の見切れは許容しますが、中央側の端が見切れるなど測れない場合は `-1` です。どちらもセンチメートル単位の実距離ではありません。

## Arduinoとの通信

カメラは各フレームの検出結果を1行のCSV形式 `V3` で送ります。カメラ側のUART1は、FPIOAで **35番をTX、34番をRX** に割り当て、115200bps・8N1に設定しています。Arduino側は `Serial1` を115200bpsで受信します。Mega 2560ではSerial1のRXは19番です。カメラTXからMega RX1へ接続し、GNDを共通にします。

送信する項目は次の順です。前・後は画像上で設定したミラーを示します。

```text
V3,ボール角,ボール画素数,ボールミラー,黄前角,黄前角幅,黄後角,黄後角幅,青前角,青前角幅,青後角,青後角幅,黄後bottomGap,青後bottomGap
```

角度・角幅・`bottomGap` の `-1` は未検出または測定不可です。ボールの画素数は未検出時0、ミラー番号は `0=未検出`、`1=前方`、`2=後方` です。行末は改行です。Arduino側はデータを改行までためて検証し、有効な行だけを採用します。V1・V2も受信できますが、守備の下端距離はV3が必要です。

Arduinoでは最後の有効フレームから200msを超えるとカメラ情報を未検出として扱います。ゴール方向を見失ったときの姿勢目標の保持時間1500msは、これとは別に管理しています。Macへ接続するUSBシリアルと、カメラからMegaへ接続するUARTは別の通信経路です。USBにログが出るだけでは、カメラからの受信成功は確定しません。

## 自分で確かめる

1. カメラの映像を表示し、正面・後方に対象を置いてROIと前後が合っているか確認します。枠が別の物体を囲むときは、照明とLAB閾値を確認します。
2. 対象を機体前方の中央、左、右へ動かし、ボールの送信角が約90°を中心に左右で変わることを確認します。後方でも同様に270°付近を確認します。反射方向が逆なら `FRONT_ANGLE_SIGN` / `BACK_ANGLE_SIGN` を確認します。
3. 実際に中央に置いた対象が90°や270°からずれる場合は、`FRONT_CENTER_POS` / `BACK_CENTER_POS` を調整します。既知の角度に対象を置いたときのずれを見て、視野角も校正します。
4. カメラ側の表示にある `tx=V3,...` と、ArduinoのUSBログにある `camera`、`cameraBall`、`yellow`、`blue`、`ownRear`、`bottomGap` を照合します。`camera=0` が続く場合はUARTの配線・共通GND・通信速度を確認します。ログの詳しい使い方は[シリアルデバッグ手順](../.agents/skills/rcj-robot-diagnostics/references/arduino-serial.md)にあります。
5. ゴールまでの前後位置を使う場合は、機体を水平にし、機体中心からゴールラインまでの距離を測りながら `bottomGap` を確認します。撮影角度、ゴールの色、見切れによって値が変わります。

Arduino側の `USE_CAMERA_BALL_ANGLE` が有効な場合、攻撃走行ではカメラのボール角を優先し、見えない場合はIRを使います。通常守備ではIRを優先し、IRが未検出ならカメラを使います。実際の選択処理は [`readControlFrame()`](../src/main.cpp) で確認できます。

画像処理の調整方法と書き込み手順は[カメラの設定](../camera/README.md)、守備時の利用方法は[守備の説明](../camera/DEFENSE.md)を参照してください。

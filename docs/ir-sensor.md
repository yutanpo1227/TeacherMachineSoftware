# IRセンサーでボールの方向を知る

このページでは、ロボットの周囲に配置したIR受光素子から、赤外線を出すボールの**方向**を求める方法を説明します。センサーの取り付け、入力の計測、方向の計算、走行制御への受け渡しを順番に追うと、同じ考え方を別の機体にも応用できます。

実装は [IRSensor.h](../lib/IRSensor/IRSensor.h) と [IRSensor.cpp](../lib/IRSensor/IRSensor.cpp)、走行制御での採用は [main.cpp](../src/main.cpp) の `readControlFrame()` にあります。

## 1. 何を測るか

2026年の国際ルールでは、2対2のSoccer Infrared（旧Lightweight）は公称直径42 mmのオレンジ色のIR発光球を使用します。ボールの外観はカメラで、発光する赤外線はIR受光素子で捉えられます。参加する大会での使用球も確認してください。[2026年のボール・コート仕様](../.agents/skills/rcj-robot-diagnostics/references/competition-specs-2026.md)

このマシンのIR処理は、ボールが機体から見てどちらの方向にあるかを求めます。計測したパルス幅を方向の計算に使いますが、ボールまで何cmあるかは計算しません。`readDistance()` は常に `-1` を返します。

## 2. センサーの配置と角度

使用する受光素子は **TSSP58038** です。`IRSensor irSensor = IRSensor(22, 8);` により、自作センサー基板の8素子をArduino Megaのデジタルピン22〜29で読みます。ソフトウェアでは、番号順のセンサーが車体周囲に45度間隔で置かれているものとして計算します。

| センサー番号 | Megaの入力ピン | 計算上の方向 |
| --- | --- | --- |
| 0 | 22 | 右 0° |
| 1 | 23 | 右前 45° |
| 2 | 24 | 前 90° |
| 3 | 25 | 左前 135° |
| 4 | 26 | 左 180° |
| 5 | 27 | 左後ろ 225° |
| 6 | 28 | 後ろ 270° |
| 7 | 29 | 右後ろ 315° |

この表はコード内の番号と角度の対応です。新しい機体でそのまま使うときは、実際の受光素子の向き・配線順がこの表と一致していることを、ボールを各方向に置いて確かめます。センサーは `INPUT_PULLUP` に設定され、現在の実装ではTSSP58038の出力が検出時にLOWになることを前提にしています。受光素子の電源や信号配線は、その回路と部品仕様に合わせて確認してください。

## 3. パルス幅から方向を計算する

`readAngle()` が呼ばれると、8個のセンサーを番号順に測ります。

1. `pulseIn(pin, LOW, 3000)` でLOWパルスの長さをマイクロ秒単位で測定します。各センサーにつき最大3000 µs待ち、タイムアウトした場合は0になります。
2. 測定結果が20 µs未満のセンサーは方向計算に入れません。
3. 残った各センサーについて、その方向を向くベクトルを作り、測定したパルス幅を重みとして足し合わせます。
4. 合計ベクトルの方向を `atan2` で計算し、0〜359度へ正規化して整数として返します。反応が一つもなければ `-1` を返します。

たとえば前のセンサーだけが反応した場合は約90度です。右前と前の両方が反応した場合、2つの値の重みを反映した中間方向になります。これは説明用の例で、反射や受光状態によって実際の値は変わります。

センサーは同時ではなく順番に読まれます。各入力で待つため、受光がない場合も含め、センサーの読み取りに時間がかかります。また、異なる方向の反応が打ち消し合う場合、合計ベクトルが小さくなり、微小な差で算出角度が変わる可能性があります。現状はその方向の信頼度を判定していません。

## 4. カメラとどう使い分けるか

`readControlFrame()` ではIRとカメラを両方読み取り、その後で走行に使うボール角度を選びます。

- **通常の守備**では、IRが検出できればIRの角度を使います。IRが未検出ならカメラの角度を使います。
- **通常の攻撃と、守備から切り替わった一時攻撃**では、`USE_CAMERA_BALL_ANGLE` が有効な場合はカメラを優先し、カメラで未検出ならIRを使います。
- 守備から攻撃への切り替え時間は、IRではなく前方カメラの連続検出で判定します。現在の待ち時間は守備設定で変更できます。

選ばれた方向は、そのまま車輪のPWMになるわけではありません。攻撃中は接近・回り込みの方向に変換され、守備中は横移動などの判断に使われます。さらに姿勢補正や白線による停止・退避が車輪への指令に影響します。

## 5. ログで確かめる

ArduinoのUSBログを115200 bpsで開くと、現行設定では `telemetry` 行に次の値が含まれます。ポートの特定と記録の手順は [Arduino CLIとシリアルデバッグ](../.agents/skills/rcj-robot-diagnostics/references/arduino-serial.md) を参照してください。

| 値 | 意味 |
| --- | --- |
| `ir` | IRセンサーが計算したボール方向。`-1` は未検出。 |
| `cameraBall` | カメラが検出したボール方向。`-1` は未検出。 |
| `ball` | そのときの走行処理で採用しているボール方向。 |
| `role`・`state` | 設定された役割と、守備・攻撃などの状態。 |

例えば、機体を固定して電池入りのIRボールを前・右・左へ順に置き、`ir` がそれぞれおおむね90°・0°・180°になるか確認します。`ball` が `ir` と違っていても、攻撃中にカメラが優先されていればあり得る動作です。値が想定と逆方向なら、ソフトウェア上の番号と実際の受光素子の配線・向きを照合します。

IRで検出できない場合は、ボールの電池と発光、受光素子の電源、信号配線、共通GNDを順に確認します。カメラで色が見えることと、IR受光ができることは別々に確認できます。床に置く前に、出力される方向と車輪が回ろうとする向きを見てから走行を試します。

# 白線・姿勢・モーターの動き

このページは、ボールを追う指令が、白線と機体の向きを考慮した4輪の動きに変わるまでを説明します。プログラムと実機を対応させながら読むため、以下の順番で扱います。

1. 白線センサーが白線を検出する方向を求める。
2. ジャイロとカメラのゴール方向から、機体の向きのずれを求める。
3. 移動方向・白線・姿勢のずれを合成し、各車輪へPWMを送る。

走行全体の判断は [main.cpp](../src/main.cpp)、白線の計測は [LineSensor.cpp](../lib/LineSensor/LineSensor.cpp)、ジャイロは [GyroSensor.cpp](../lib/GyroSensor/GyroSensor.cpp)、4輪への配分は [MotorController.cpp](../lib/MotorController/MotorController.cpp) にあります。パラメーターは [RobotConfig.h](../src/RobotConfig.h) と [MotorControllerConfig.h](../lib/MotorController/MotorControllerConfig.h) にあります。

## 機体から見た角度

ボール・白線・移動指令は、ロボットを上から見た次の角度で扱います。

```text
                  前 90°
                     ↑
       左 180° ← ロボット → 右 0°
                     ↓
                 後 270°
```

ジャイロの `yaw` はBNO055が返す方位で、上図の対象物の方向とは別の値です。プログラムには電源投入時の機体の向きを自動的に0度に設定する処理はありません。角度差が0°と360°をまたぐ場合は、近い方向の差になるよう計算します。

## 白線センサー

### 役割と接続

機体の周囲に配置された8個の反射センサーで床の白線を検出します。各センサーのアナログ値を対応する閾値と比較し、閾値を超えたセンサーが白線に反応していると判定します。[main.cpp](../src/main.cpp) は入力をA0から8個として作成し、各閾値は `LINE_SENSOR_THRESHOLDS` に指定しています。

`LineSensor::readAngle()` は、反応したセンサーそれぞれの方向を足し合わせて白線の方向を返します。センサー番号 `i` の方向は `i × 360 ÷ 8` 度として計算されます。白線を検出していない場合とセンサーを無効にした場合の値は `-1` です。実機で番号と方向が合っているかは、白線を機体の右・前・左・後ろに置いて確認します。

複数のセンサーが同時に反応した場合、`readVectorMagnitude()` は方向のまとまりを0〜1で表します。一方側に集中すると1に近く、反対側にも反応があって互いに打ち消し合うと0に近づきます。この値は白線の距離ではありません。方向の揺れを抑えるため `readAngle()` は前回値を使って平滑化し、60度を超える急変は前回の値を保持します。白線が見えなくなると履歴を消します。攻撃へ切り替わる際にも攻撃用フィルターを初期化します。

### 白線を検出したときの動き

通常のOFFENSEでは、白線の方向とボールの方向の角度差が45度以内なら停止します。白線がボール方向と異なる場合、方向のまとまりが0.75未満なら白線の反対へ、0.75以上なら元の移動方向に白線から離れる方向を加えて動きます。これらの境界は [MotorControllerConfig.h](../lib/MotorController/MotorControllerConfig.h) で調整できます。

通常のDEFENSEでは、白線を走行の判断には使いません。表示用には別の `LineSensor` インスタンスで観測します。守備から攻撃へ移った後は攻撃用の白線処理を使います。切り替えた瞬間に白線を踏み、自ゴールが後方に見えるなどの条件が成立した場合には、最大700msの前方への白線離脱が先に実行されます。条件や距離判定は [守備の説明](../camera/DEFENSE.md) にあります。

白線センサーは同じ白色の外周線とペナルティエリア線の種類を直接識別しません。上の白線離脱も、線そのものを区別するのではなく、カメラの自ゴール検出と姿勢などの条件を使います。

### 閾値の調整

床と白線それぞれの上に各センサーを置き、生の値を比べてから `LINE_SENSOR_THRESHOLDS` を決めます。判定は「アナログ値が閾値より大きいと白線」です。照明、センサーの高さ、床材、テープの種類で値が変わるため、実際のコートでも確認します。`LineSensor::printValues()` は8個の生値をUSBシリアルへ出力するための関数ですが、通常のループからは呼ばれていません。PITCHの `line` と `lineStrength` は検出後の方向とまとまりで、生の8値ではありません。

## ジャイロとゴール方向

BNO055はI2Cアドレス `0x28` で初期化し、`readYawAngle()` で方位を整数として返します。`ENABLE_GYRO_SENSOR` が有効で初期化に失敗した場合は、メッセージを出してその場で処理を止めます。無効時は方位の読み取り値が0になります。

カメラでゴールを検出すると、[GoalHeading.cpp](../lib/GoalHeading/GoalHeading.cpp) が「いまのジャイロ方位」と「機体から見たゴール角」から目標方位を更新します。通常攻撃では相手ゴールを前方へ、守備では自ゴールを後方へ向けることを目指します。ゴールが見えなくなっても、最後の目標を `GOAL_HOLD_MS` の1500ms保持し、その後はジャイロ0度を基準にします。

守備中に自ゴールが見えなくなり、カメラとの通信が続いているときは、0度の±5度以内を200ms維持するまでその場で向き直ります。その後は0度を中心に左右15度を交互に見ながら後退します。自ゴールが再び見えれば、その情報を使う守備に戻ります。カメラとの通信断中の通常守備は停止します。攻撃中の扱いを含め、詳しい優先順位は [守備の説明](../camera/DEFENSE.md) を参照してください。

通常走行の姿勢補正では、誤差が3度以内なら補正0、範囲を超えたら比例係数0.8で算出し、補正出力の絶対値をPWM 20〜50に収めます。白線を検出していないとき、ずれが90度以上ならその場の旋回を優先します。`SPEED` を0にした姿勢テストでは別の旋回設定を使います。

## オムニホイールとPWM

[MotorController::moveDirection()](../lib/MotorController/MotorController.cpp) は、移動したい方向と速度、姿勢のずれ、白線情報を受け取ります。白線の停止・退避を処理した後、移動方向を各車輪の駆動方向に投影します。車輪ごとに違う向き・強さを組み合わせることで、機体の向きを保ちながら前後左右や斜めへ移動できます。

その後、姿勢を直すための旋回成分を4輪に加えます。車輪の出力がPWMの上限255を超えないよう、旋回分の余裕を残して並進の強さを制限します。例えば `SPEED=230` は移動指令の設定値であり、4輪が常に230で回る意味ではありません。斜め移動や姿勢修正では各車輪の値が異なります。

各 [Motor](../lib/Motor/Motor.cpp) は、指令の符号で回転方向を決め、絶対値をPWMとしてモータードライバーへ出します。0なら出力を0にします。この構成には車輪の回転速度を測る処理がないため、PWMだけから実際の速度は判断できません。配線は [main.cpp](../src/main.cpp) の `motor1`〜`motor4` の生成箇所で確認します。

## 実機で確かめる順番

1. 車輪を床から離し、白線を各センサーの下に順番に置く。PITCHやUSBシリアルで `line` が期待する方向を指すか、白線がないとき `-1` になるか確認する。表示値と攻撃中の制御値は別インスタンスなので、完全に同じとは限らない。
2. `SPEED=0` の姿勢テストで、機体を少し回したときに目標方向へ向き直るか確認する。ジャイロの `yaw` と制御の `error` を記録する。
3. 通常の速度に戻し、ボール・ゴール・白線の条件を一つずつ変えて、前進、横移動、旋回、白線停止を確認する。ゴールの見切れや照明でも検出値は変化する。
4. 床に置いたときに動きが弱ければ、PWMの指令だけでなく、走行中の電池パックとモータードライバー入力の電圧も比べる。

USBシリアルは接続時にArduinoがリセットされる場合があります。ポート選択やログの記録手順は [実機調査スキルのArduino CLI・シリアル手順](../.agents/skills/rcj-robot-diagnostics/references/arduino-serial.md) と [PITCHデバッガー](../robot-debugger/README.md) を参照してください。
